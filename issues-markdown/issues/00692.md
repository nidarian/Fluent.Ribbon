# Issue #692: Add dedicated secondary KeyTip on SplitButton

- **State:** closed
- **Author:** Pyth0ff
- **Created:** 2019-02-06T10:57:39Z
- **Closed:** 2019-02-09T17:13:51Z
- **Labels:** Feature :1st_place_medal:
- **Original:** https://github.com/fluentribbon/Fluent.Ribbon/issues/692

We switched recently from the Microsoft control to the fluent.ribbon control. We have the case that we have multiple middle sized SplitButtons side-by-side and the key tips are sometimes overlapping, because of the default applied postfix.

First I thought that this is a nice way to reach the primary action faster, if the primary action has its own key tip, but in general it is also reachable as a menu item of the button and for this menu item the user has to type one key more than for example in the windows explorer or in the Microsoft version of the control. The user is already navigating via keyboard so there is no real benefit to have it like this, if the user has to press a key more to access the primary action directly or via the menu.

Having two key tips makes the aligning of them harder, in case of multiple middle sized elements are grouped, which can cause overlapping. I saw that Microsoft tries to prevent this issue in Office 365 by moving the key tip vertical to the top, if the element is in the first row and to the bottom, if it is in the third row.

**Request:** Please provide an option two disable the primary key tip and provide an option to have a single key tip to access the menu of the splitbutton, to have the same behavior like with the Microsoft ribbon control or the Windows Explorer.
