# PR #1286: Allow KeyTipService to serve control hosts

KeyTipService is tied to Ribbon, preventing an ItemsControl host with direct child commands from using the same Alt keytips and focus behavior.

Add public IKeyTipServiceHost and an interface-based service constructor, preserving KeyTipService(Ribbon) as a forwarding overload. Ribbon implements the host operations with its existing menu/start-screen target order and tab focus behavior. Root adorner, forwarding and unmatched-input cancellation use the host control identity; focus backup is retained when focus starts outside the host.

Public-event STA tests cover direct-child Alt activation, Escape/Alt cancellation, command execution, focus return, unmatched root input, attach lifecycle and Ribbon constructor compatibility. The new helper uses initial WPF activation and closes windows when setup fails. This contribution is based on stable v11.0.2 and is independent of the quick-access factories.

Validation: VS18 MSBuild Release/AnyCPU net462 build and full Framework suite with process-local DPIUNAWARE. The original TestImmediateDismissIfNoMatchesInRootLayer also fails on unpatched v11.0.2 in this shared Windows session; it is retained unchanged as a known activation failure. All new host regressions pass. The combined wrapper additionally builds/tests on net6.0-windows and net8.0-windows and passes separate net48 source/package keytip probes, including Danish æ, ø and å.
