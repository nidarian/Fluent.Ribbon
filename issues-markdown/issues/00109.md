## chdft commented on 2015-05-06T23:14:46Z

If you know all tabs at compile-time, it is probably the best idea to add them in xaml, because the gain by having a smaller visual tree is probably not worth the additional work. 
It also sounds like you might want to use contextual groups, which allow you to group tabs that are only useful/available in a certain context. That way the user gets a visual clue, that there are additional commands available based on the context. You can also easily hide entire `RibbonContextualTabGroup`s by setting their visibility property.
If you want to handle the `RibbonTabItem`s in the views, you can bind the `Tabs` property of the ribbon to a `ObservableCollection<RibbonTabItem>` which is composed and changed based on the current view in the code behind. You can access wpf resources with `this.Resources["yourKey"]` from the code behind, but if you define the tabs in a central xaml file anyway, you might as well just define them inside the ribbon of the target window (unless of course you will use the tabs in more than one window).
