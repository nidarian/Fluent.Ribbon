# Issue #1272: Fluent Ribbon combined with Wpf-ui (lepo.co) or C#9+ theme have too large button headers

- **State:** closed
- **Author:** wojciechsura
- **Created:** 2026-04-05T13:18:34Z
- **Closed:** 2026-04-28T16:24:55Z
- **Labels:** WontFix :-1:
- **Original:** https://github.com/fluentribbon/Fluent.Ribbon/issues/1272

When combined with WPF-UI theming library, button headers are too big (apparently the theming library manages to somehow force size of the labels) and overflow from buttons.

To reproduce: add WPF-UI library, configure it by adding to the App.xaml resources:

```
             xmlns:ui="http://schemas.lepo.co/wpfui/2022/xaml"

            <ResourceDictionary.MergedDictionaries>
                <ui:ThemesDictionary Theme="Light" />
                <ui:ControlsDictionary />
            </ResourceDictionary.MergedDictionaries>
```

Or turn on the new theming mechanism present since C#9:

```
<App (...) ThemeMode="Light" (...) />
```

Then add a button with two-line caption. The caption will be too big and will overflow from the button.

Obviously external libraries may interfere with how Fluent.Ribbon works, but maybe it might be a good idea to force the size of button header captions, since other elements of the UI are fixed too? Or even enforce (or template-bind) size of the font of all UI elements, so that it can be controlled from a central place?

## Environment

```text
- Fluent.Ribbon: __11.0.2__
- Windows __11__
- .NET __10.0__
```

## batzen commented on 2026-04-05T17:14:54Z

That's not a bug in Fluent.Ribbon but a side effect of the way WPF-UI does it's work.
They [manipulate](https://github.com/lepoco/wpfui/blob/e6e22e3389872f2aba90c079ee64a007116e01d3/src/Wpf.Ui/Controls/TextBlock/TextBlockMetadata.cs#L15) the default value for various TextBlock properties (i guess for other types too).
It's none of their business to change the default values for all TextBlocks as that's one of the "special" controls you don't want to touch when doing styling from a library as it affects everything that intentionally inherits it's values from parent controls.
I won't add code to fight libraries that do their styling by violating that.
Adding WPF-UI not only breaks buttons with two-line captions but every control that uses a TextBlock.
