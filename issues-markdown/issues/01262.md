# Issue #1262: Lazy loading of RibbonTabItem

- **State:** closed
- **Author:** ekalchev
- **Created:** 2026-01-21T08:00:55Z
- **Closed:** 2026-01-27T19:36:09Z
- **Labels:** -
- **Original:** https://github.com/fluentribbon/Fluent.Ribbon/issues/1262

I’ve identified that Fluent.Ribbon parses and instantiates controls for all RibbonTabItems at startup, even when those tabs are not visible. This adds an unnecessary performance penalty to application startup. Ideally, I would like the XAML for hidden RibbonTabItems to be parsed and instantiated only when the tab is selected.

I’ve implemented a workaround, but it is far from ideal. My current approach creates placeholder tabs that contain only the header text. When a tab is selected, the placeholder is replaced with the real tab. The main drawback is that I need to manually transfer all properties from the placeholder to the real tab, and this approach is likely to introduce additional, unforeseen issues.

My understanding is that I cannot simply use a Control with a ControlTemplate for each tab and rely on WPF’s layout system to instantiate the template on demand. In particular, placing a RibbonGroupBox inside a ControlTemplate does not work as expected.

Is there better approach for this?

```CSharp
public class LazyRibbonTabItem : RibbonTabItem
{
    protected override void OnSelected(RoutedEventArgs e)
    {
        base.OnSelected(e);

        // Find the Ribbon that owns this tab
        var ribbon = this.ParentOfType<Ribbon>();
        if (ribbon == null) return;

        // We must swap asynchronously to avoid breaking 
        // the current selection event cycle
        Dispatcher.BeginInvoke(new Action(() =>
        {
            int index = ribbon.Tabs.IndexOf(this);
            if (index != -1)
            {
                // Instantiate the real tab
                var realTab = new ConvertTab();

                // Copy essential properties from placeholder to real tab
                // (Optional: ensures header/keytips match what was in XAML)
                realTab.Header = this.Header;

                // 1. Remove dummy, 2. Insert real one
                ribbon.Tabs.RemoveAt(index);
                if (index >= ribbon.Tabs.Count)
                {
                    ribbon.Tabs.Add(realTab);
                }
                else
                {
                    ribbon.Tabs.Insert(index, realTab);
                }

                // 3. Select the new real tab
                realTab.IsSelected = true;
            }
        }), DispatcherPriority.Send);
    }
}
```

## batzen commented on 2026-01-27T17:19:24Z

There is currently no way to achieve the same behavior as with a regular TabControl/TabItem.

What you could do is to load/create the groups on demand.
Like:
```
public class LazyRibbonTabItem : RibbonTabItem
{
    protected override void OnSelected(RoutedEventArgs e)
    {
        base.OnSelected(e);

        // Find the Ribbon that owns this tab
        var ribbon = this.ParentOfType<Ribbon>();
        if (ribbon == null) return;

        if (this.Groups.Count is 0)
        {
            this.LoadGroups();
        }
    }
}
```

You could then create sub-types for each of your tabs or create some bridge code that loads your groups from a datatemplate lazyly to be able to create your groups and their content in XAML.

Would that work/feel better for you?

## ekalchev commented on 2026-01-27T19:36:09Z

I end up using this approach below. My tabs have this base class. It is specific for my use case, where each of my tab has corresponding XAML file and code behind. I delay the instantiation of the tab content by not calling InitializeComponent() in the constructor but in OnSelected. Not the best but it works

```CSharp
public abstract class LazyRibbonTabItem : RibbonTabItem
{
    private bool initialized = false;

    protected LazyRibbonTabItem ()
    {
    }

    protected void EnsureInitialized()
    {
        if(initialized)
        {
            return;
        }

        if (this is IComponentConnector componentConnector)
        {
            componentConnector.InitializeComponent();
            initialized = true;
        }
        else
        {
            throw new InvalidOperationException("The tab must implement IComponentConnector to initialize its components.");
        }
    }

    protected void VerifyInitialized()
    {
        if (!initialized)
        {
            throw new InvalidOperationException("Tab not initialized. Ensure Initialize() is called before using the tab.");
        }
    }

    protected override void OnSelected(RoutedEventArgs e)
    {
        EnsureInitialized();
        base.OnSelected(e);
    }
}
```
