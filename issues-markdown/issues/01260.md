## The Challenge

After implementing custom tab row theming (see: [Fluent.Ribbon Custom Theming Guide](./fluent-ribbon-theming-guide.md)), a common next step is differentiating the active/selected tab from inactive tabs.

**Goals:**
- Active tab should visually "pop" from the tab row
- Support both light and dark themes
- Respond to accent color changes
- Update immediately when user clicks different tabs

**Why it's difficult:**
The `RibbonTabItem` control has a `Background` property, but the internal template doesn't use it for rendering. Standard WPF approaches like style triggers don't work.

---

## What Doesn't Work

### 1. Direct Property Setting on RibbonTabItem

```csharp
// Find selected tabs and set their background
if (element is Fluent.RibbonTabItem tabItem && tabItem.IsSelected)
{
    tabItem.Background = new SolidColorBrush(Colors.White);
}
```

**Why it fails:** The control template uses internal bindings. The `Background` property exists but isn't used for visual rendering.

### 2. Style Triggers

```xml
<Style TargetType="{x:Type fluent:RibbonTabItem}">
    <Style.Triggers>
        <Trigger Property="IsSelected" Value="True">
            <Setter Property="Background" Value="White"/>
        </Trigger>
    </Style.Triggers>
</Style>
```

**Why it fails:** Same reason - the template ignores the `Background` property regardless of how it's set.

### 3. Resource Overrides

```xml
<SolidColorBrush x:Key="Fluent.Ribbon.Brushes.RibbonTabItem.Active.Background"
                 Color="White" />
```

**Why it fails:** Fluent.Ribbon loads its resources after yours, overwriting them. And templates use `StaticResource`, so runtime changes don't apply.

---

## What Works: Visual Tree Detection

The solution extends the visual tree walk approach. Instead of trying to set properties on `RibbonTabItem` directly, we:

1. Detect when we're inside a selected tab by checking `RibbonTabItem.IsSelected`
2. Pass that state down to child elements during the tree walk
3. Apply the active tab color to the child Panels and Borders (which DO respond to direct property setting)

### Why This Works

- **Child elements are normal WPF controls** - Panels, Borders, etc. respond to `Background` property changes
- **IsSelected is readable** - We can check the property even if we can't use it for styling
- **Visual tree walk gives us access** - We can reach inside the template's visual structure

## Complete Working Solution

### Step 1: Define Theme Brushes

Add both `TabRowBrush` (inactive tabs) and `ActiveTabBrush` (selected tab) to your theme files.

```xml
<!-- LightTheme.xaml -->
<ResourceDictionary xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
                    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml">

    <!-- Your existing colors -->
    <Color x:Key="PrimaryLightColor">#BBDEFB</Color>
    <Color x:Key="SurfaceColor">#FFFFFF</Color>

    <!-- Tab brushes -->
    <SolidColorBrush x:Key="TabRowBrush" Color="{StaticResource PrimaryLightColor}" />
    <SolidColorBrush x:Key="ActiveTabBrush" Color="#FFFFFF" />
</ResourceDictionary>
```

```xml
<!-- DarkTheme.xaml -->
<ResourceDictionary xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
                    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml">

    <!-- Your existing colors -->
    <Color x:Key="BackgroundColor">#1E1E1E</Color>
    <Color x:Key="SurfaceColor">#2D2D30</Color>

    <!-- Tab brushes - note the inverted logic for dark mode -->
    <SolidColorBrush x:Key="TabRowBrush" Color="{StaticResource BackgroundColor}" />
    <SolidColorBrush x:Key="ActiveTabBrush" Color="{StaticResource SurfaceColor}" />
</ResourceDictionary>
```

**Design rationale:**
- **Light mode:** Inactive tabs = accent tint, Active tab = white (pops against colored background)
- **Dark mode:** Inactive tabs = dark background, Active tab = slightly lighter surface (pops by being lighter)

### Step 2: Modify the Visual Tree Walker

```csharp
/// <summary>
/// Applies theme to the Ribbon by walking the visual tree.
/// Call after window loads and after theme/accent changes.
/// </summary>
public void ApplyThemeToRibbon()
{
    var background = Application.Current.Resources["BackgroundBrush"] as SolidColorBrush;
    var surface = Application.Current.Resources["SurfaceBrush"] as SolidColorBrush;
    var foreground = Application.Current.Resources["TextPrimaryBrush"] as SolidColorBrush;
    var border = Application.Current.Resources["BorderBrush"] as SolidColorBrush;
    var tabRow = Application.Current.Resources["TabRowBrush"] as SolidColorBrush;
    var activeTab = Application.Current.Resources["ActiveTabBrush"] as SolidColorBrush;

    if (background == null || foreground == null) return;

    // Fallbacks
    tabRow ??= background;
    activeTab ??= surface ?? background;

    WalkVisualTreeAndApplyTheme(MyRibbon, background, surface, foreground, border,
                                 tabRow, activeTab, false, false);
}

/// <summary>
/// Recursively walks the visual tree and applies theme colors.
/// </summary>
/// <param name="inTabRow">Whether we're inside the tab row container</param>
/// <param name="inActiveTab">Whether we're inside a selected tab</param>
private void WalkVisualTreeAndApplyTheme(
    DependencyObject parent,
    SolidColorBrush background,
    SolidColorBrush surface,
    SolidColorBrush foreground,
    SolidColorBrush border,
    SolidColorBrush tabRow,
    SolidColorBrush activeTab,
    bool inTabRow,
    bool inActiveTab)
{
    if (parent == null) return;

    // Detect if we're entering the tab row area
    bool isTabRowElement = false;
    if (parent is Grid grid)
    {
        if (grid.Name == "TabsGrid" || grid.Name == "PART_TabsGrid")
        {
            isTabRowElement = true;
            inTabRow = true;
        }
    }

    // Detect if we're entering a selected/active tab
    bool isActiveTabElement = false;
    if (parent is Fluent.RibbonTabItem tabItem && tabItem.IsSelected)
    {
        isActiveTabElement = true;
        inActiveTab = true;
    }

    // Determine effective background based on context
    // Priority: active tab > tab row > default background
    SolidColorBrush effectiveBackground = background;
    if (inActiveTab)
        effectiveBackground = activeTab;
    else if (inTabRow)
        effectiveBackground = tabRow;

    // Apply colors to current element
    if (parent is Panel panel)
    {
        panel.Background = effectiveBackground;
    }
    else if (parent is Border borderElement)
    {
        borderElement.Background = effectiveBackground;
        if (border != null) borderElement.BorderBrush = border;
    }
    else if (parent is Control control)
    {
        // Skip buttons/textboxes - they should keep surface color
        if (!(control is Button || control is TextBox))
        {
            control.Background = effectiveBackground;
        }
        if (foreground != null) control.Foreground = foreground;
    }

    // Recurse to children
    int childCount = VisualTreeHelper.GetChildrenCount(parent);
    for (int i = 0; i < childCount; i++)
    {
        var child = VisualTreeHelper.GetChild(parent, i);
        WalkVisualTreeAndApplyTheme(
            child, background, surface, foreground, border, tabRow, activeTab,
            isTabRowElement ? true : inTabRow,
            isActiveTabElement ? true : inActiveTab);
    }
}
```

### Step 3: Handle Tab Selection Changes

The visual tree walk is a snapshot. When the user clicks a different tab, we need to re-walk to update colors.

```csharp
public MainWindow()
{
    InitializeComponent();

    // Apply theme after window loads
    Loaded += (s, e) => ApplyThemeToRibbon();

    // Re-apply when tab selection changes
    MyRibbon.SelectedTabChanged += Ribbon_SelectedTabChanged;
}

private void Ribbon_SelectedTabChanged(object sender, SelectionChangedEventArgs e)
{
    // Re-apply theme to update active tab highlighting
    ApplyThemeToRibbon();
}
```

## Dark Mode Accent Tints

When supporting user-selectable accent colors, dark mode needs special handling. Bright accent tints look wrong on dark backgrounds.

### The Problem

```csharp
// This works for light mode but looks bad in dark mode
var lightColor = LightenColor(accentColor, 1.7);
Application.Current.Resources["TabRowBrush"] = new SolidColorBrush(lightColor);
```

### The Solution: Theme-Aware Color Generation

```csharp
public void SetAccentColor(string hexColor)
{
    var color = (Color)ColorConverter.ConvertFromString(hexColor);

    // Generate light shade for light mode
    var lightColor = LightenColor(color, 1.7);

    // Update TabRowBrush based on current theme
    if (Application.Current.Resources.Contains("BackgroundColor") &&
        Application.Current.Resources.Contains("TabRowBrush"))
    {
        var bgColor = (Color)Application.Current.Resources["BackgroundColor"];

        // Detect theme by background brightness
        // Light backgrounds (R > 128) = light mode
        bool isLightMode = bgColor.R > 128;

        if (isLightMode)
        {
            // Light mode: use bright accent tint
            Application.Current.Resources["TabRowBrush"] = new SolidColorBrush(lightColor);
        }
        else
        {
            // Dark mode: blend 20% accent + 80% dark background
            // Creates subtle colored darkness instead of bright tint
            var darkAccent = Color.FromRgb(
                (byte)(color.R * 0.2 + bgColor.R * 0.8),
                (byte)(color.G * 0.2 + bgColor.G * 0.8),
                (byte)(color.B * 0.2 + bgColor.B * 0.8));
            Application.Current.Resources["TabRowBrush"] = new SolidColorBrush(darkAccent);
        }
    }

    // Don't forget to re-apply after accent change!
    // (Call from your settings UI after this method)
}

private Color LightenColor(Color color, double factor)
{
    return Color.FromRgb(
        (byte)Math.Min(255, color.R + (255 - color.R) * (factor - 1.0)),
        (byte)Math.Min(255, color.G + (255 - color.G) * (factor - 1.0)),
        (byte)Math.Min(255, color.B + (255 - color.B) * (factor - 1.0)));
}
```

### Why 20/80 Blend Ratio?

- **Too much accent (40%+):** Colors become too bright, defeating dark mode purpose
- **Too little accent (10%):** Accent barely visible, feels like broken theming
- **20% accent:** Subtle but noticeable tint, stays dark, shows user's color choice

## Key Insights

### 1. RibbonTabItem.Background is Decorative Only

The property exists for API completeness but the template doesn't use it. Don't waste time trying to make it work.

### 2. IsSelected is Readable, Just Not Styleable

You can check `tabItem.IsSelected` in code, you just can't use it in XAML triggers effectively. Use it to detect state during visual tree walk.

### 3. Child Elements Respond to Direct Setting

The Panels and Borders inside `RibbonTabItem` are standard WPF controls. They respond normally to `Background` property changes.

### 4. Re-walk on Every Relevant Change

The visual tree walk produces a snapshot. You need to re-walk after:
- Window loads
- Theme changes (light/dark)
- Accent color changes
- Tab selection changes

### 5. Dark Mode Needs Different Math

Light mode: Lighten the accent color (multiply toward white)
Dark mode: Blend accent with dark background (weighted average)

### 6. Performance is Fine

Visual tree walking takes <10ms typically. Calling it on tab selection doesn't cause visible delay or flicker because property changes apply immediately.
