# PR #1285: Support derived quick-access ComboBox and SplitButton copies

- **State:** closed
- **Author:** cbra-caa
- **Created:** 2026-10-09T09:12:26Z
- **Closed:** 2026-10-09T09:32:04Z
- **Labels:** -
- **Original:** https://github.com/fluentribbon/Fluent.Ribbon/pull/1285

CreateQuickAccessItem currently constructs concrete ComboBox and SplitButton controls, so derived controls must duplicate the inherited binding and event setup to create matching quick-access copies.

Add protected virtual, parameterless CreateQuickAccessComboBox and CreateQuickAccessSplitButton factories and retain all clone setup in CreateQuickAccessItem. The base factories return fresh controls; SplitButton copies still disable adding their button to quick access.

Two STA factory-contract tests prove each override is called once and its known derived instance receives the inherited setup. This contribution is based on stable v11.0.2 and is independent of the keytip-host contribution.

Validation: VS18 MSBuild Release/AnyCPU net462 build; full Framework suite with process-local DPIUNAWARE. The original TestImmediateDismissIfNoMatchesInRootLayer remains a known activation failure in this shared Windows session and also fails on the unpatched release. New factory tests pass. The combined wrapper additionally builds/tests on net6.0-windows and net8.0-windows and passes the separate net48 source/package factory checks.
