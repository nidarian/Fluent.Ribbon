# PR #1282: General purpose fix for missing/untransfered ItemsControl QAT properties

- **State:** closed

This is a general purpose fix for *all* possible missing QAT properties for `ItemsControl` & `Selector` based controls.

The quick access creation/binding logic seems quite fragmented in general.
A lot of logic happens in shared methods, then there are base class methods that bind some properties, omit others. Then there may be overloads that are extended COPIES of base implementations but that do not call the base versions.

All in all I'm not shocked that there are issues in there.

I _think_ at a minimum this could benefit from a cleanup where duplicated/repeated binds are eliminated and code is centralized.

---

To me the entire `IQuickAccessItemProvider.CreateQuickAccessItem()` logic smells like a poor man's attempt at templating/framework element factory replication. It knows how to create controls and set some linked states in them. But it does so in a fragmented, non-idiomatic and non-extensible way.

My gut instinct here is to say: That's fricken templating. Why not *implement* it as templating.

Every Fluent control that supports addition to QAT get's a 'QATTemplate' property of type `DataTemplate`. The QAT uses *that* as ItemTemplate per toolbar element. Each element's `DataContext` *is* the originating control. That should allow clean xaml based template definition & binding. Might need some custom Markupextension for some wiring (private event handlers in particular come to mind). Also there may be some shenanigans with logical child shuffling I'm not seeing clear enough.

But in general that would allow a cleaner XAML based (and thus idiomatic & extensible) approach to "What does this look like in the QAT"). Would allow reuse of (shared) styles for common properties and should allow way easier discovery of overlooked (or repeat used) links.

## DoctorVanGogh commented on 2026-08-24T12:38:28Z

Well, I'd argue having a XAML backed Template is _way_ more idiomatic than any roll-your-own codebehind approach.

As for collection synchronization: I'd classify that as its own defect. No collection should exist *without* a paired bindable dependency property. `ItemsControl` has both `Items` _and_ `ItemsSource`. One is for inlined elements, one for bindable/styled/animated sources.
In the same vein all collection properties should have a corresponding `FooSource` dependency property for each `Foo` collection. And yes, I'm aware that even the framework does not fully adhere to this ;)

That dependency property could either be directly defined by the control *or* as an interim solution via simple attached properties. The `CollectionSyncHelper` already does 95% of the work. Putting that together with a generic "this is a an attached property of `IEnumerable<T>` . whatever you set here will be synced to target collection Y" is not that much further.

Here's a quick solution for the collection sync binding (with a custom sync helper):

### generic helpers
```cs
    public class ListSyncHelper<TOwner, TItem, TCollection, TListAccessSemantics>
        where TOwner : DependencyObject
        where TCollection : IList<TItem>
        where TListAccessSemantics : struct, ListSyncHelper<TOwner, TItem, TCollection, TListAccessSemantics>.IListAccessor 
    {

        public interface IListAccessor {
            public TCollection GetList(TOwner owner);
        }

        protected static TListAccessSemantics Access => default(TListAccessSemantics);

        /// <summary>Collection to store collection change handlers - to be able to unsubscribe later.</summary>
        private static readonly ConditionalWeakTable<TOwner, EventHandler<NotifyCollectionChangedEventArgs>> _handlers = new();

        private static readonly ConditionalWeakTable<TOwner, IEnumerable?> _collections = new();

        public static void Sync(TOwner owner, IEnumerable? items) {
            if (_collections.TryGetValue(owner, out var previous)) {
                // Unsubscribe from old collection.
                RemoveChangeTracker(previous as INotifyCollectionChanged, owner);
            }

            ClearItems(owner);

            if (items is not null) {
                // special case: Compositecollection (note: nested not supported)
                if (items is CompositeCollection collection)
                    items = collection.Cast<CollectionContainer>().SelectMany(cc => cc.Collection.Cast<object>());
                AddItems(owner, items);

                // Subscribe to future changes.
                AddChangeTracker(items as INotifyCollectionChanged, owner);
            }
            _collections.Remove(owner);
            _collections.Add(owner, items);
        }

        private static void AddChangeTracker(INotifyCollectionChanged? tracker, TOwner owner) {
            if (tracker == null)
                return;

            EventHandler<NotifyCollectionChangedEventArgs> h = (_, ne) => OnCollectionChanged(ne, owner);
            _handlers.Add(owner, h);
            CollectionChangedEventManager.AddHandler(tracker, h);
        }

        private static void RemoveChangeTracker(INotifyCollectionChanged? tracker, TOwner owner) {
            if (tracker == null)
                return;

            if (_handlers.TryGetValue(owner, out EventHandler<NotifyCollectionChangedEventArgs>? h)) {
                CollectionChangedEventManager.RemoveHandler(tracker, h);
                _handlers.Remove(owner);
            }
        }

        public static void ClearItems(TOwner owner) {
            var collection = Access.GetList(owner);
            collection.Clear();
        }


        static void OnCollectionChanged(NotifyCollectionChangedEventArgs ne, TOwner owner) {
            switch (ne.Action) {
                case NotifyCollectionChangedAction.Reset:
                    ClearItems(owner);
                    AddItems(owner, ne.NewItems ?? (_collections.TryGetValue(owner, out var existing) ? existing : null));
                    break;
                case NotifyCollectionChangedAction.Add:
                    AddItems(owner, ne.NewItems);
                    break;
                case NotifyCollectionChangedAction.Move:
                    Action<NotifyCollectionChangedEventArgs> move = Access.GetList(owner) switch {
                        // observable collections offer natrive moves
                        ObservableCollection<TItem> oc => (eventArgs => oc.Move(eventArgs.OldStartingIndex, eventArgs.NewStartingIndex)),
                        // any other collection we need to emulate moves
                        TCollection col => eventArgs => {
                            var item = col[eventArgs.OldStartingIndex];
                            col.RemoveAt(eventArgs.OldStartingIndex);
                            col.Insert(eventArgs.NewStartingIndex, item);
                        }
                    };
                    move(ne);
                    break;
                case NotifyCollectionChangedAction.Remove:
                    RemoveItems(owner, ne.OldItems);
                    break;
                case NotifyCollectionChangedAction.Replace:
                    if (ne.OldItems is not null) {
                        RemoveItems(owner, ne.OldItems);
                    }
                    if (ne.NewItems is not null) {
                        AddOrInsert(owner, ne.NewItems, ne.NewStartingIndex);
                    }
                    break;
            }
        }

        private static void ProcessItems(
            IEnumerable? items,
            Action<TItem> processingAction
        ) {
            foreach (TItem item in items ?? Enumerable.Empty<TItem>()) {
                processingAction(item);
            }
        }

        private static void AddItems(TOwner owner, IEnumerable? items)
            => ProcessItems(items, Access.GetList(owner).Add);

        private static void AddOrInsert(TOwner owner, IEnumerable? items, int targetIndex) {
            var collection = Access.GetList(owner);
            Action<TItem> insert = targetIndex is not -1
                ? it => collection.Insert(targetIndex, it)
                : collection.Add;
            ProcessItems(items?.Cast<TItem>().Reverse(), insert);
        }

        private static void RemoveItems(TOwner owner, IEnumerable? items) 
            => ProcessItems(items, c => Access.GetList(owner).Remove(c));



    }

    public class ObservableCollectionSyncHelper<TOwner, TItem, TCollectionAccessSemantics>
        : ListSyncHelper<TOwner, TItem, ObservableCollection<TItem>, TCollectionAccessSemantics>
        where TOwner : DependencyObject
        where TItem : DependencyObject
        where TCollectionAccessSemantics : struct, ListSyncHelper<TOwner, TItem, ObservableCollection<TItem>, TCollectionAccessSemantics>.IListAccessor;

```

### specific adaptations
```cs
    public class ItemsControlHelper {
        private readonly struct GroupStyleAccessor : ObservableCollectionSyncHelper<ItemsControl, GroupStyle, GroupStyleAccessor>.IListAccessor {
            public ObservableCollection<GroupStyle> GetList(ItemsControl owner)
                => owner.GroupStyle;
        }


        public static IEnumerable<GroupStyle>? GetGroupStyleItemsSource(ItemsControl obj) {
            return (IEnumerable<GroupStyle>?)obj.GetValue(GroupStyleItemsSourceProperty);
        }

        public static void SetGroupStyleItemsSource(ItemsControl obj, IEnumerable<GroupStyle>? value) {
            obj.SetValue(GroupStyleItemsSourceProperty, value);
        }

        // Using a DependencyProperty as the backing store for GroupStyleItemsSource.  This enables animation, styling, binding, etc...
        public static readonly DependencyProperty GroupStyleItemsSourceProperty =
            DependencyProperty.RegisterAttached(
                "GroupStyleItemsSource", 
                typeof(IEnumerable<GroupStyle>), 
                typeof(ItemsControlHelper), 
                new PropertyMetadata(null)
            );


    }
```

#### Xaml
```xaml
<Style x:Key"Foo.Styles.QAT.SplitButton"
       TargetType="{x:Type fluent:SplitButton}"
       BasedOn="...">
	<Setter Property="..." Value="..." />
	<Setter Property="(xyz:ItemsControlHelper.GroupStyleItemsSource)" Value="{Binding Path=GroupStyle, Mode=OneWay}" />
        ...
</Style>

<DataTemplate x:Key="Foo.Templates.QAT.SplitButton"
	      DataType="{x:Type fluent:SplitButton}">
	<fluent:SplitButton Style="{StaticResource Foo.Styles.QAT.SplitButton}" />
</DataTemplate>
```

public DataTemplate? QATTemplate {get; set;}

   element.DataContext = this;
   return element;
}
