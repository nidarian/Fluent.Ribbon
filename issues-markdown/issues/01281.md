# Issue #1281: SplitButton will not apply ItemTemplateSelector within QuickAccess

- **State:** closed
- **Author:** DoctorVanGogh
- **Created:** 2026-08-17T05:15:51Z
- **Closed:** 2026-08-23T10:22:33Z
- **Labels:** Bug :lady_beetle:
- **Original:** https://github.com/fluentribbon/Fluent.Ribbon/issues/1281

If you use a SplitButton and set an `ItemTemplateSelector` that selector works within the scope of the ribbon itself.
If you add the SplitButton to the quick access toolbar the `ItemTemplateSelector` will **not** be applied and you get plain (ambient) "templates" applied for whatever you items happen to be. Any and all commands, styles, templating etc is then obviously lost for the quickaccess version.

Snoop view of the visual tree of a splitbutton within quickaccess that is fed some arbitrary int array. Note the plain `TextBlock`under the `ContentPresenter`s.
<img width="466" height="229" alt="Image" src="https://github.com/user-attachments/assets/ae60b051-104c-4f31-9db3-a1168de28da0" />

If you use a "plain" `ItemTemplate` that _will_ be applied to the quick access version.
(Snoop view of the visual tree using just an item template):

<img width="359" height="200" alt="Image" src="https://github.com/user-attachments/assets/f3ae36b4-84be-4701-b27c-989645906831" />

It seems _only_ ItemTemplate is correctly applied to whatever template is used for quickaccess elements. Not `ItemTemplateSelector` (haven't checked if `ItemStringFormat` gets applied).

Demo project: [WpfApp25.zip](https://github.com/user-attachments/files/31129856/WpfApp25.zip)

Start, pick "Templated" button, in new window add both split buttons to quick access. one has working commands for the popup, the other doesnt.
