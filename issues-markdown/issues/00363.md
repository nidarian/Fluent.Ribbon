## korneliuscode commented on 2016-10-23T20:10:39Z

Thanks for your comment. If this would be the case then it might be with the converter.
I bind it with an IValueConverter for en enum to the ViewModel

I have a couple of ToggleButtons like this:

```
<Fluent:ToggleButton GroupName="Group" Content="ABC" Header="ABC" IsChecked="{Binding Path=SelectedType, Mode=TwoWay,Converter={StaticResource enumConverter}, ConverterParameter=ABC}" />
<Fluent:ToggleButton GroupName="Group" Content="DEF" Header="DEF" IsChecked="{Binding Path=SelectedType, Mode=TwoWay,Converter={StaticResource enumConverter}, ConverterParameter=DEF}" />
```

This is the Converter.

```
   public class EnumConverter : IValueConverter
    {
        public object Convert(object value, Type targetType, object parameter, CultureInfo culture)
        {
            if (value == null || parameter == null)
                return false;

            string checkValue = value.ToString();
            string targetValue = parameter.ToString();
            return checkValue.Equals(targetValue, StringComparison.InvariantCultureIgnoreCase);
        }

        public object ConvertBack(object value, Type targetType, object parameter, CultureInfo culture)
        {
            if (value == null || parameter == null)
                return null;

            bool useValue = (bool)value;
            string targetValue = parameter.ToString();
            if (useValue)
                return Enum.Parse(targetType, targetValue);

            return null;
        }
    }
```

The issue seems to be the returning `null` at the `ConvertBack` for the unselected item.

But what should it return so the unchecked toggle button knows how to handle? Actually it works fine except for the red border.

## batzen commented on 2016-10-27T17:40:37Z

ConvertBack is used to convert the value from the togglebutton back to your binding source/viewmodel.

Is "SelectedType" a nullable type?
If not, that should be your problem and you should better return the default enum value in that case.
