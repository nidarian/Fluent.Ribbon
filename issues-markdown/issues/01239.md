I'm used to customize the Window menu (i.e. System menu), and I encounter some problems with the version 11 (it seems the version 10 also have some, but less important, issue). I published a small project in https://github.com/YetAnotherCodeMaker/FluentRibbonSamples/tree/main/V11RibbonWindowMenuIssue to show the problem.

You can set the project property `FluentRibbonVersion` to 0, 10 or 11 to generate the application without Fluent Ribbon or with version 10 or 11. This generates a small application with a simple window in which the Window menu can be reverted to its default state by clicking the "Rebuild Window Menu" button (which invokes the Win32 `GetSystemMenu` function and try to get a native handle to it; a border indicates if this handle is null or not).

My analysis is the following (the `ResizeMode` of the Window is set to `CanMiminize`)

### without Fluent Ribbon
#### initial menu
`Restore`, `Size` and `Maximize` are disabled (this is expected)
#### menu after rebuild
same as initial (this is expected too)

### with Fluent Ribbon version 10
#### initial menu
`Restore` and `Size` are disabled, `Maximised` is enabled (while it shouldn't)
#### menu after rebuild
often, the first time the menu is opened, all items are enabled, the initial situation returns from the second time it is opened

### with Fluent Ribbon version 11
#### initial menu
as in version 10
#### menu after rebuild
the menu is empty (a native handle cannot even be retrieved)

```
        var oldUseNativeCaptionButtons = this.UseNativeCaptionButtons;
        this.UseNativeCaptionButtons = true;
        var menuHandle = NativeMethods.GetSystemMenu(windowHandle, false);
        this.UseNativeCaptionButtons = oldUseNativeCaptionButtons;
```

```
using System.Windows;

using Fluent;

static class Program
{
    const string fluentDictionaryUri =
        "pack://application:,,,/Fluent;Component/Themes/Generic.xaml";

    [STAThread]
    static int Main()
    {
        Application application =
            new()
            {
                Resources =
                {
                    MergedDictionaries =
                    {
                        new ResourceDictionary()
                        {
                            Source =
                                new(
                                    fluentDictionaryUri,
                                    UriKind.RelativeOrAbsolute)
                        }
                    }
                }
            };

        application.Startup += (sender, e) =>
        {
            foreach (var value in new bool?[] { null, false, true })
                CreateWindow(value).Show();
        };

        return application.Run();
    }

    static Window CreateWindow(bool? useNativeCaptionButtons)
    {
        RibbonWindow window =
            new()
            {
                Width = 480,
                Height = 320,
                Title = nameof(RibbonWindow.UseNativeCaptionButtons) + " = ",
                Tag = useNativeCaptionButtons
            };

        if (useNativeCaptionButtons.HasValue)
        {
            window.UseNativeCaptionButtons = useNativeCaptionButtons.Value;
            window.Title = $"{window.UseNativeCaptionButtons}";
        }
        else
            window.Title = "default";

        return window;
    }
}
```

## batzen commented on 2025-04-04T11:56:10Z

On Windows 10 the window background is opaque.
On Windows 11 the window background is transparent if any backdrop effect is active, which is the default.
The property UseNativeCaptionButtons is inherited and not yet fully visually supported in Fluent.Ribbon. That's why i didn't mention it in the changelog.
Getting it to work right on Windows 10 would have been a nightmare, so i decided to postpone implementation till I don't have to support Windows 10 anymore, which is sometime next year.
