    }

## batzen commented on 2015-08-27T17:26:46Z

The problem with loading the controls again on application startup is caused by the implementation of QAT state management.
The code is very simple and stupid. It just saves the positions of the items and tries to grab the corresponding items when it's loaded again.
One saved item looks like this "0,3,1,0,0,3,0,0," and nothing more.
So for your dynamically added items you run into the problem that aren't part of the ribbon when the state is loaded.

I would strongly advice you to not used the included method of saving and loading QAT items as you will, most probably, change the positions of your generated or generate them in a different order in the future. The result you'll get then is that you get some "random" controls restored to QAT.

I don't use dynamic QAT and state management at all at work because our ribbon is massively generated at runtime. There is not a single fixed item in our Ribbon.
To be honest, I won't change/improve the current QAT saving and loading because I don't use it at all.

## batzen commented on 2015-08-27T18:46:58Z

Your second problem is caused by WPF itself, at least I guess so. 
We got a converter which creates a new Image and sets your BitmapImage as it's source.
When i replace your code with

```
Icon = new Image { Source = new BitmapImage(new Uri(@"Images\Green.png", UriKind.Relative)) },
```

It works as expected. 
As that's essentially exactly the same we do in our converter, I don't know why it behaves differently...
