Hey batzen, this is part of a very big solution :)) So I only copied and pasted the relevant section, I don't have it in a separate project/solution. :)))

I currently found a workaround by inheriting BackstageTabControl and overriding the function IsItemItsOwnContainerOverride

```
    public class MyBackstageTabControl : BackstageTabControl
    {
        protected override bool IsItemItsOwnContainerOverride(object item)
        {
            return base.IsItemItsOwnContainerOverride(item) || item is System.Windows.Controls.TreeView;
        }
    }
```

I then use MyBackstageTabControl in my xaml instead of BackstageTabControl.

The thing is the style of the tree view looked at start odd, but by defining a different style I managed to make it look ok.

## batzen commented on 2019-06-19T17:55:18Z

@soumyanayankar That does not work because the `ItemTemplate` is being used for the right hand content area, in this case.
So you have to use an `ItemContainerStyle` or `ItemContainerStyleSelector` which should be inherited from `BackstageTabControlItemContainerStyleSelector` (otherwise you loose separator styling etc.).

In the style you return from the selector you can then set the content of the tab item to your liking.

The reason for all this is that the `BackstageTabControl` behaves more like a `TabControl` than an `ItemsControl` like `ListBox` for example. And the fact that the method `IsItemItsOwnContainerOverride` only works the way you want if you provide real controls instead of viewmodels.

Your last option might be to just ignore those things, inherit from `BackstageTabControl` and override things like `GetContainerForItemOverride` etc.
