# Issue #550: Binding doesn't work between ToggleButton and Button

- **State:** closed
- **Author:** JohnyL
- **Created:** 2018-03-28T05:57:11Z
- **Closed:** 2018-03-31T08:24:28Z
- **Labels:** -
- **Original:** https://github.com/fluentribbon/Fluent.Ribbon/issues/550

I have ToggleButton and Button. I created binding between them so that when ToggleButton is not checked, the Button would be disabled, and vice versa. Here's XAML:
```
<Fluent:ToggleButton
        x:Name="toggleNewOrderDetailEdit"
        IsChecked="False"
        Header="Edit"/>
<Fluent:Button
        Header="Save"
        x:Name="btnSaveNewOrderDetail"
        IsEnabled="{Binding ElementName=toggleEditNewOrderDetail,
                            Path=IsChecked,
                            UpdateSourceTrigger=PropertyChanged}"/>
```

This didn't work. Then I decided to make it manually - through events, and then I discovered that `IsEnabled` property of `Button` is of type `bool` and `IsChecked` property of `ToggleButton` is of type `bool?`. Then I decided to create a value converter:
```
[ValueConversion(typeof(bool?), typeof(bool))]
public class NullableBoolToBoolConverter : IValueConverter
{
    public object Convert(object value, Type targetType, object parameter, CultureInfo culture) =>
        ((bool?)value).Value;
    public object ConvertBack(object value, Type targetType, object parameter, CultureInfo culture) =>
	throw new NotImplementedException();
}
```
Add converter to XAML:
```
<Fluent:RibbonWindow.Resources>
	<local:NullableBoolToBoolConverter x:Key="NullableBoolToBoolConverter"/>
</Fluent:RibbonWindow.Resources>
<Fluent:Button
        Header="Save"
        x:Name="btnSaveNewOrderDetail"
        IsEnabled="{Binding ElementName=toggleEditNewOrderDetail,
                            Path=IsChecked,
                            UpdateSourceTrigger=PropertyChanged},
                            Converter={StaticResource NullableBoolToBoolConverter}"/>
```
But to my amusement, the converter wasn't called at all! Looked like it was totally ignored. Moreover, I watched the Output pane - no binding errors were detected.

---
### Environment

- Fluent.Ribbon: 6.1.0.233
- Windows: 10 Pro
- .NET Framework 4.7.1

## JohnyL commented on 2018-03-29T12:32:23Z

Finally, I localized a problem. So, fasten your seat-belts. :)

I created a brand-new application with two windows: WPF Window and Ribbon Window. Each of windows contains two elements: `ToggleButton` and `Button`. The `Button`'s `IsEnabled` property is bound to `Toggle`'s `IsChecked` property. The logic in my original program was the following:
1. Show login window.
2. If login is successful, show main window.

In my test app, the main window could be either of both windows. Login page merely sets `DialogResult = true`. The `ShutdownMode` is `OnLastWindowClose`. This effectively allows us to manipulate windows in `Startup` method. I have expanded my logic a bit: I added the logic when main window is run directly (i.e. without going through the login window). So, I added two directives: `SKIP_LOGIN` and `USE_RIBBON` to manipulate the states. Let's check all four possible states. Here's the code:
```
#define SKIP_LOGIN
#define USE_RIBBON

private void OnStartup(object sender, StartupEventArgs e)
{
#if SKIP_LOGIN
    #if USE_RIBBON
        var root = new WPFRibbonWindow();
        root.Show();
    #else
	var root = new WPFWindow();
	root.Show();
    #endif
#else
    #if USE_RIBBON
	var root = new WPFRibbonWindow();
    #else
	var root = new WPFWindow();
    #endif
	var login = new LoginWindow();
	login.ShowDialog();
	if (login.DialogResult == true)
	{
	    root.Show();
	}
#endif
}
```

__State 1. Direct run / Use WPF Window__ (`SKIP_LOGIN` is _on_, `USE_RIBBON` is _off_)
Binding works.

__State 2. Show login page / Use WPF Window__ (`SKIP_LOGIN` is _off_, `USE_RIBBON` is _off_)
Binding works.

__State 3. Direct run / Use Ribbon Window__ (`SKIP_LOGIN` is _on_, `USE_RIBBON` is _on_)
Binding works.

__State 4. Show login page / Use Ribbon Window__ (`SKIP_LOGIN` is _off_, `USE_RIBBON` is _on_)
Binding **does not** work.

So, as you see, binding in WPF window works no matter how it was run. But in the case of Ribbon Window, binding works when running it directly, but refuses to work when running indirectly. This clearly shows that this is some bug.

## JohnyL commented on 2018-03-30T17:30:34Z

I have found a solution!

I really wasn't glad to take another route for login window, but I had no choice. I was about to give up... When I read over and over again you words "_WPF thinks it should load ribbon tabs_", I came up with idea - what if the problem is with `InitializeComponent()` method call? And I did two changes:

**1. Removed `InitializedComponent()` method call from `RibbonWindow`'s constructor:**
```
public WPFRibbonWindow()
{
    //InitializeComponent();
}
```

**2. Made explicit call of `InitializeComponent()` in `Application` class:**
```
var root = new WPFRibbonWindow();
var login = new LoginWindow();
login.ShowDialog();
if (login.DialogResult == true)
{
    root.InitializeComponent(); //Explicit call
    root.Show();
}
else
    root?.Close();
```
And... It worked!! I understand that this is a workaround, but at least it allows me to keep the flow of my application as I designed. :) However, there's one caveat: if you subscribe to `Initialized` event and will call `MessageBox.Show()` in its event handler, then the binding won't work.

**P.S.** As for closing window, I can do it by adding one line:
```
if (login.DialogResult == true)
{ ... }
else
    root?.Close();
```
