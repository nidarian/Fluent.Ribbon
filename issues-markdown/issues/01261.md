**A guide to fixing unreadable button text in dark mode Fluent.Ribbon applications.**

## The Problem

After implementing custom dark mode theming for Fluent.Ribbon (tab row colors, backgrounds, etc.), button text often remains black - completely unreadable against dark backgrounds.

**Symptoms:**
- Ribbon button headers (text labels) are black in dark mode
- DropDownButton, SplitButton, ToggleButton text all affected
- Standard WPF controls in the same window show correct light text
- Only Fluent.Ribbon button controls have the issue

**Why it's confusing:**
The `Foreground` property exists on these controls. Setting it via code-behind compiles and runs without error. But the text color doesn't change.

---

## What Doesn't Work

### 1. Direct Property Setting via Code-Behind

```csharp
// Walking the visual tree and setting Foreground
if (parent is Fluent.Button fluentButton)
{
    fluentButton.Foreground = new SolidColorBrush(Colors.White);
}
else if (parent is Fluent.DropDownButton dropDown)
{
    dropDown.Foreground = new SolidColorBrush(Colors.White);
}
else if (parent is Fluent.SplitButton splitButton)
{
    splitButton.Foreground = new SolidColorBrush(Colors.White);
}
```

**Result:** No effect. The property is set, but text remains black.

### 2. Setting Foreground on Child Text Elements

```csharp
// Trying to reach the actual text elements
if (parent is TextBlock textBlock)
{
    textBlock.Foreground = foreground;
}
else if (parent is AccessText accessText)
{
    accessText.Foreground = foreground;
}
else if (parent is ContentPresenter contentPresenter)
{
    TextElement.SetForeground(contentPresenter, foreground);
}
```

**Result:** No effect. Template bindings override these settings.

### 3. TextElement.SetForeground Attached Property

```csharp
// Catch-all attempt using attached property
TextElement.SetForeground(element, foreground);
```

**Result:** No effect.

### 4. Overriding Fluent.Ribbon Resource Brushes

```csharp
// Trying to override the brushes Fluent.Ribbon uses internally
Application.Current.Resources["Fluent.Ribbon.Brushes.LabelTextBrush"] = whiteBrush;
Application.Current.Resources["Fluent.Ribbon.Brushes.IdealForegroundColorBrush"] = whiteBrush;
Application.Current.Resources["Fluent.Ribbon.Brushes.BlackBrush"] = whiteBrush;
```

**Result:** No effect. Internal templates use `StaticResource`, not `DynamicResource`.

### 5. ControlzEx.Theming.ThemeManager

```csharp
// Using the built-in theme manager
ControlzEx.Theming.ThemeManager.Current.ChangeTheme(this, "Dark.Blue");
// or
ControlzEx.Theming.ThemeManager.Current.ChangeTheme(Application.Current, "Dark.Blue");
```

**Result:** Changes accent colors but doesn't fix button text foreground.

---

## Why Nothing Works

Fluent.Ribbon button control templates are designed with:

1. **Internal template bindings** - The template controls text rendering, ignoring the `Foreground` property set externally
2. **StaticResource usage** - Internal brushes are resolved at load time, not dynamically
3. **Template-level triggers** - Visual states and triggers override external property values
4. **Sealed rendering logic** - Text elements inside the template are not accessible for theming via code

This is different from standard WPF controls or even the ribbon's structural elements (Panels, Borders) which DO respond to direct property setting via visual tree walk.

---

## The Solution

Add `Foreground` binding directly in XAML using `DynamicResource`:

```xml
<fluent:Button Foreground="{DynamicResource TextPrimaryBrush}"
               Header="My Button"
               Size="Large"
               Icon="{StaticResource MyIcon}"/>
```

### Why This Works

1. **DynamicResource** - Creates a live binding that updates when the theme changes
2. **XAML declaration** - Takes precedence over template defaults
3. **Explicit property** - The template respects explicitly declared properties in the element

---

## Complete Implementation

### Step 1: Define Theme Brushes

```xml
<!-- LightTheme.xaml -->
<SolidColorBrush x:Key="TextPrimaryBrush" Color="#212121" />
<SolidColorBrush x:Key="TextSecondaryBrush" Color="#757575" />

<!-- DarkTheme.xaml -->
<SolidColorBrush x:Key="TextPrimaryBrush" Color="#FFFFFF" />
<SolidColorBrush x:Key="TextSecondaryBrush" Color="#B0B0B0" />
```

### Step 2: Apply to All Ribbon Buttons

```xml
<fluent:RibbonGroupBox Header="File Operations">
    <fluent:Button Foreground="{DynamicResource TextPrimaryBrush}"
                   Header="Open"
                   Size="Large"
                   Icon="{StaticResource OpenIcon}"
                   Command="{Binding OpenCommand}"/>

    <fluent:Button Foreground="{DynamicResource TextPrimaryBrush}"
                   Header="Save"
                   Size="Large"
                   Icon="{StaticResource SaveIcon}"
                   Command="{Binding SaveCommand}"/>

    <fluent:SplitButton Foreground="{DynamicResource TextPrimaryBrush}"
                        Header="Export"
                        Size="Large"
                        Icon="{StaticResource ExportIcon}">
        <fluent:MenuItem Header="Export as PDF"/>
        <fluent:MenuItem Header="Export as CSV"/>
    </fluent:SplitButton>

    <fluent:DropDownButton Foreground="{DynamicResource TextPrimaryBrush}"
                           Header="Recent"
                           Size="Middle"
                           Icon="{StaticResource RecentIcon}">
        <fluent:MenuItem Header="File1.txt"/>
        <fluent:MenuItem Header="File2.txt"/>
    </fluent:DropDownButton>
</fluent:RibbonGroupBox>
```

### Step 3: Don't Forget Group Headers

If you use custom group header templates:

```xml
<DataTemplate x:Key="GroupHeaderWithSubtitle">
    <StackPanel HorizontalAlignment="Center">
        <TextBlock Text="{Binding}"
                   Foreground="{DynamicResource TextPrimaryBrush}"
                   HorizontalAlignment="Center"
                   FontSize="11"/>
        <TextBlock Text="{Binding RelativeSource={RelativeSource AncestorType=fluent:RibbonGroupBox}, Path=Tag}"
                   Foreground="{DynamicResource TextSecondaryBrush}"
                   FontSize="9"
                   Opacity="0.6"
                   HorizontalAlignment="Center"/>
    </StackPanel>
</DataTemplate>
```

### Step 4: Handle Mixed Controls

If you have standard WPF buttons alongside Fluent.Ribbon buttons:

```xml
<!-- Standard WPF Button also needs the binding -->
<Button Foreground="{DynamicResource TextPrimaryBrush}"
        Content="Load Cached Results"
        Command="{Binding LoadCachedCommand}"/>
```

## Key Insights

### 1. Two Different Theming Approaches

| Element Type | Theming Approach |
|-------------|------------------|
| Ribbon structure (tab row, panels, borders) | Visual tree walk with direct property setting |
| Declared controls (buttons, dropdowns) | XAML `DynamicResource` bindings |

### 2. Don't Fight the Framework

If setting a property via code-behind doesn't work, the answer is usually XAML. Fluent.Ribbon templates are designed to work with XAML declarations, not runtime property manipulation.

### 3. Visual Tree Walk Still Has Value

The visual tree walk approach works perfectly for:
- Tab row background colors
- Active/selected tab highlighting
- Border and panel backgrounds
- Internal structural elements

It just doesn't work for templated control text.

### 4. This is the Proper WPF Pattern

Using `DynamicResource` for theme-aware properties is the standard WPF approach. It's not a hack - it's how WPF theming is meant to work.

## Summary

| Problem | Solution |
|---------|----------|
| Button text black in dark mode | Add `Foreground="{DynamicResource TextPrimaryBrush}"` to XAML |
| Code-behind Foreground setting ignored | Use XAML binding instead |
| Group header text wrong color | Add Foreground binding to DataTemplate TextBlocks |
