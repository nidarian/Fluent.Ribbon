# Issue #1252: "Can not modify the logical children for this node at this time because a tree walk is in progress" exception when when DynamicResource on RibbonGroupBox updates during theme switch

- **State:** closed

- **Labels:** -
- **Original:** https://github.com/fluentribbon/Fluent.Ribbon/issues/1252

Switching the application theme at runtime (updating Application.Resources.MergedDictionaries) causes WPF to walk the logical tree to invalidate resource references. During that walk, Fluent.RibbonGroupBox (via LogicalChildSupportHelper) attempts to AddLogicalChild in response to a property change, which triggers:

System.InvalidOperationException: Cannot modify the logical children for this node at this time because a tree walk is in progress.

This exception happens occasionally.

## batzen commented on 2025-11-01T06:59:16Z

That's not a bug in Fluent.Ribbon.
You can reproduce the issue without using Fluent.Ribbon.
Use the following code to trigger theme changes and adjust the code in `IconThemeChangeHandler` to also handle `Button` (from WPF)
```
<Expander Header="{DynamicResource Fluent.Ribbon.Images.DefaultPlaceholder}">
    <Button Content="Crash on click" addLogicalChildRepro:ThemesManager.ApplicationThemeChangeHandler="{StaticResource iconThemeChangeHandler}" Click="ButtonBase_OnClick" />
</Expander>
```

The issue here is:
- Setting `ApplicationCurrentTheme` value on `Window` triggers a logical tree walk
- Tree walk hits the `Expander` (or `RibbonGroupBox`) and sets `IsLogicalChildrenIterationInProgress` to `true`
- Our button is part of the logical tree, get's hit by the tree walk and triggers `OnThemeChanged`
- Resources get changed and another tree walk starts (this shouldn't even be possible, IMHO as it destroys the correct values for `IsLogicalChildrenIterationInProgress` of the previous iteration)
- Tree walk hits the `Expander` (or `RibbonGroupBox`) and tries to change a resource reference on it which influences the logical children of it, but in fact WPF is still handling the previous tree walk and `IsLogicalChildrenIterationInProgress` is still `true`

To prevent this you can either place your theme change button somewhere where it doesn't cause such reentrancy issues, or delay the code to change resources via Dispatcher.BeginInvoke.
