Previously I used the IsSelected property in code behind, it worked correctly.

But recently I was developing a new software based on the MVVM mode , I tried to bind the `IsSelected` property of ribbon tab with my view model.

For example, I have defined an enumeration like this.

```C#
enum RibbonTabNames : int
{
    None = -1,
    Start = 0,
    Setting = 1,
    Qc = 2,
    Om = 3,

    EditOm = 4
}
```

And Then, I created a converter.

```C#
[ValueConversion(typeof(RibbonTabNames), typeof(bool))]
public class SelectRibbonContextualTabGroupConverter : IValueConverter
{
    public object Convert(object value, Type targetType, object parameter, CultureInfo culture)
    {
        RibbonTabNames currentTab = (RibbonTabNames)value;
        RibbonTabNames requiredTab = (RibbonTabNames)System.Convert.ToInt32(parameter);

        return currentTab == requiredTab;
    }

    public object ConvertBack(object value, Type targetType, object parameter, CultureInfo culture)
    {
        bool isSelected = (bool)value;
        if (!isSelected)
        {
            return RibbonTabNames.None;
        }
        return (RibbonTabNames)int.Parse(parameter.ToString());
    }
}
```

At last, the view model code like below.

```C#
public MainViewModel()
{
    SelectedRibbonTab = RibbonTabNames.Data;
}
```

The xaml code is like this.

```XAML
IsSelected="{Binding SelectedRibbonTab, ConverterParameter=1, Converter={StaticResource selectRibbonContextualTabGroupConverter}}"
```

What I want to achieve is `Setting`  tab to be selected, but actually still got the `Start` tab selected

## batzen commented on 2020-02-09T14:38:59Z

The issue with using `IsSelected` as the driver for tab selection is that, before selecting a new tab, the ribbon de-selects the previous one. In addition to that you now have multiple potential sources for the selected tab item as your property also binds two-way. As soon as the ribbon says one tab got de-selected or selected your converter triggers multiple times, thus potentially changing the value back and forth.
This causes your binding value to "flipper" around.

A better approach would be to use the selection properties like `SelectedTabItem` or `SelectedTabIndex` from `Ribbon`. That way you got one binding point instead of multiple.
