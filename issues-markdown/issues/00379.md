# Issue #379: BackstageTabControl SelectionChanged event affected by DataGrid or Listview selection change

- **State:** closed
- **Author:** bacca87
- **Created:** 2016-11-28T21:10:25Z
- **Closed:** 2017-03-26T13:58:50Z
- **Labels:** Question :question:
- **Original:** https://github.com/fluentribbon/Fluent.Ribbon/issues/379

If you put a DataGrid or Listview inside a BackstageTabItem, and then you click on a row with data, the Datagrid/Listview SelectionChanged and the BackstageTabControl SelectionChanged too are fired.
This is very annoying because I use the BackstageTabControl SelectionChanged for loading the data inside the Listview.

How can I prevent this issue?

```
<Fluent:BackstageTabControl Name="menuBackstageTabControl" SelectionChanged="BackstageTabControl_SelectionChanged">
	<Fluent:BackstageTabItem Header="Informations"/>
	<Fluent:BackstageTabItem Name="factoriesBackstageTab" Header="Factories">
		<Grid>
			<Grid.ColumnDefinitions>
				<ColumnDefinition></ColumnDefinition>
				<ColumnDefinition></ColumnDefinition>
			</Grid.ColumnDefinitions>
			<Grid.RowDefinitions>
				<RowDefinition></RowDefinition>
				<RowDefinition></RowDefinition>
			</Grid.RowDefinitions>
			<ListView Name="factoriesListView"
					  Grid.RowSpan="2" 
					  Grid.Column="0" 
					  Grid.Row="0">
				<ListView.View>
					<GridView>                                            
						<GridViewColumn Header="Name" DisplayMemberBinding="{Binding Name}" />
						<GridViewColumn Header="CompanyName" DisplayMemberBinding="{Binding CompanyName}" />
						<GridViewColumn Header="Address" DisplayMemberBinding="{Binding Address}" />
						<GridViewColumn Header="TransferType" DisplayMemberBinding="{Binding TransferType}" />
						<GridViewColumn Header="IsForfait" DisplayMemberBinding="{Binding IsForfait}" />
					</GridView>
				</ListView.View>
			</ListView>
			<Button Click="Button_Click" Grid.Row="0" Grid.Column="1"></Button>
			<Gmap:GMapControl x:Name="mapControl" Grid.Column="1" Grid.Row="1" Zoom="13" MaxZoom="24" MinZoom="1" />
		</Grid>
	</Fluent:BackstageTabItem>
	<Fluent:SeparatorTabItem />
	<Fluent:BackstageTabItem Header="Settings"/>
	<Fluent:Button Name="exitButton" Header="Exit" Click="exitButton_Click"/>
</Fluent:BackstageTabControl>
```

### Environment

- Theme __office2013__ (not needed in version 5.0 and upwards)

## bacca87 commented on 2016-11-29T18:01:53Z

At the moment, for workaround this issue, i've put all the controls inside a page and then i've just added a frame inside BackstageTabItem pointing that page.
In this way the BackstageTabControl SelectionChanged event is not affected by Listview selection changes.

## batzen commented on 2016-12-11T08:42:09Z

That's not an issue with Fluent.Ribbon, but an issue with WPF itself.
SelectionChanged is routed through all controls, you can prevent your issue by checking if the orginal source of the event is really the backstage or not.

That should solve your problem.
