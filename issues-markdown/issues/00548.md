## batzen commented on 2018-04-08T10:05:11Z

For me "theme" equals different styles and templates for controls.

If you want to start your work the starting points would be:
- Colors.xaml (just a reference file which contains all color and brush resources)
- BaseLight.xaml and BaseDark.xaml (base color schemes, in ThemeManager these are called AppTheme)
- Accent.Template.xaml (used as a template to generate the accent resource dictionaries from GeneratorParameters.json)

- BaseLight and BaseDark contain a resource named `Fluent.Ribbon.AppTheme` which is, indirectly, used in various style triggers. This is achieved by first setting the attached property `Fluent:RibbonProperties.AppTheme` to `{DynamicResource Fluent.Ribbon.AppTheme}` and then triggering on `Fluent:RibbonProperties.AppTheme`. Most of these triggers then set some attached property like `Fluent:RibbonProperties.MouseOverForeground` and don't use a special brush in the control style for the mouse over foreground. That way we are able to use different resources based on the current "app theme". I guess you'll need to introduce a few more attached properties, judging from the list you posted above. This "workaround" is need if, for one "app theme" an accent color should be used for something and in the other an "app theme" color should be used.

If you have any questions feel free to ask them here or DM me on gitter/twitter.
